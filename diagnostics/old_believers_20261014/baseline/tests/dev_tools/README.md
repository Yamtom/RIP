# Інструменти розробки

Гра цього не завантажує. EU4 читає `events/` і `localisation/` тільки в корені
мода, тож усе, що лежить тут, лишається мертвим, доки його не скопіюють назад.

## ZAZ_branch_debug

Перекидає запорізьке дерево на будь-яку з п'яти союзних гілок: чистить прапорці
`zaz_allied_*`, ставить один із них і викликає `swap_non_generic_missions`.
Подія має `is_triggered_only`, і ніщо її не викликає, тож дістатися до неї можна
було лише з консолі — саме тому їй і не місце в збірці для гравців.

Щоб скористатися нею під час випробувань, скопіюйте обидва файли назад до
`events/` і `localisation/`, а тоді в консолі:

```text
event zaz_branch_debug.1
```

Перед пакуванням приберіть їх знову.

## local_llm — локальний llama.cpp як підагент

`local_llm.py` — пул запитів до llama.cpp на `http://localhost:8080`
(Codestral-22B Q3_K_M). Гра цього не читає; це інструмент розробки.

Повний універсальний контракт, готові валідатори, кешування й приклад пакетного
запуску — у [LOCAL_LLM_GUIDE.md](LOCAL_LLM_GUIDE.md).

Заміряно на цій машині: **3.0 ток/с** на потік, **4 слоти**, `n_ctx = 8192`.
Звідси все інше.

**Чого йому не давати.** Аналізу. На проханні звірити вісім файлів
`common/opinion_modifiers` з п'ятьма правилами ванілі він вигадав вісім
порушень, яких немає («у podillia немає `yearly_decay`» — він там у всіх
п'яти), і не побачив жодного справжнього (`max = -N`, `yearly_decay = -1`).
Q3-квантизація галюцинує саме заперечення — «тут бракує X». Ніколи не питайте
його, що з чимось не так.

**Що він робить добре.** Одну коротку рядкову відповідь із фактів, які вже
лежать у промпті. Довжина виходу — це вся ціна: 900 токенів це п'ять хвилин,
15 токенів це п'ять секунд.

**Робочий шаблон:**

1. одне завдання на одиницю роботи, усі факти вписані в промпт;
2. жорсткий контракт виходу (`Title Case`, 2–6 слів, без лапок) і `stop`;
3. `check` — механічний валідатор на кожну відповідь;
4. `run_batch` жене їх по 4 слотах, відхилене перезапитує раз при `temperature=0`,
   решту віддає людині.

```powershell
python tests/dev_tools/local_llm.py     # самоперевірка на живому сервері
```

**Чого валідатор не ловить — і чому є `unique=True`.** `check` бачить лише свою
відповідь. На восьми заголовках модифікаторів думки модель видала однакове
«Ruthenian Recognition Status» і для Литви, і для Польщі — обидві пройшли
формат. Тому `run_batch` за замовчуванням відхиляє відповідь, що збігається з
чужою.

**Реальна віддача.** 8 заготовок за 26 с (6.6 ток/с сукупно) проти ~16 с
послідовно. Формат гарантовано, якість — ні: усі вісім довелося переписати.
Тобто це чернетковий генератор для об'ємної однотипної роботи, а не автор.
Для 8 рядків виграш невеликий; для 200 — відчутний.

## balance_sim — арифметика механік поза грою

`balance_sim/` містить дві моделі на C++, які повторюють числа релігійних
механік там, де їх видно. Скрипт EU4 рахує бюджет навернень усередині
`while`-циклу, який не має способу нічого надрукувати; статичні перевірки
доводять, що символи з'єднані, і не можуть сказати, що механіка перетворює цілу
державу за один такт.

На трьох запусках моделі знайшли три справжні дефекти, яких не спіймав жоден
гейт: бюджет без десятини, недосяжний найдешевший тир для малих держав і
таблицю утримання ікон, за якої за 200 років жодна лампада не гасла. Подробиці
й таблиці — у `balance_sim/README.md`.

Запуск (компілятора немає в `PATH`, потрібен `vcvars64.bat`):

```powershell
powershell -File tests/dev_tools/balance_sim/build_and_run.ps1
```
