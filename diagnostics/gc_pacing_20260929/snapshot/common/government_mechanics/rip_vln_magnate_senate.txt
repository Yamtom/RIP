# =============================================================================
# rip_vln_magnate_senate - the great Volhynian magnate families (Ostrozky,
# Sanguszko, Chartoryisky) effectively co-ruled the palatinate; the voivode
# governed only with their consent. An earlier session drafted a whole reform,
# vln_magnate_senate_reform, for this and dropped it (no authenticity-inventory
# entry, no loc, invented over the working tree) - see
# docs/GOVERNMENT_REDESIGN_PROPOSAL.uk.md R5. Its modifier numbers are reused
# here as a mechanic modifier instead of resurrecting a reform id.
#
# common/estates/RIP_magnates.txt's estate_magnates only attaches to VLN via
# vln_voivode_council (a later reform), not at T1, so plain country modifiers.
#
# Buttons-only (devshirme pattern): no powers, no .gui, vanilla Cossack
# ability sprites, no DLC gate.
#
# Fatigue guardrail: vln_cossack_host_reform (a different tier, T2) already
# carries government_abilities = cossacks_mechanic. A VLN country could hold
# both vln_voivodeship_reform (T1) and vln_cossack_host_reform (T2) at once,
# stacking two 3-button panels - `available` below retires the Senate the
# moment the Cossack Host is picked, since the register-and-Host system is
# the larger, forcelimit-tied vanilla mechanic.
# =============================================================================
