# =============================================================================
# rip_hlc_austrian_reorganization - the Austrian fork of the Galician
# Voivodeship (hlc_centralized_voivodeship_reform -> hlc_austrian_bureaucracy_
# reform -> hlc_crown_authority_reform) never had a mechanic of its own; the
# Poland fork already did (rip_hlc_boyar_council.txt's hlc_boyar_council_
# mechanic, plus has_polish_election on hlc_magnate_assembly_reform). This is
# the Austria fork's counterpart, built the same way the boyar council was.
#
# SIX DIFFERENT ORDINANCES, one button each. The author asked for six
# abilities. An earlier revision gave three ordinances an "enact" and a
# "rescind" button apiece and called that six; on screen it was two identical
# rows of three, the same three pictures twice. There is no rescind button any
# more: every ordinance is a term, not a switch.
#
#   top row     Chancery   (diplomatic power)  clerks seconded to the chancellor
#               Settlement (administrative)    settlers on the conversion rolls
#               Cadastral  (administrative)    the surveyors' land registers
#   bottom row  Urbarial   (administrative)    what each village owes its lord
#               Toleration (diplomatic)        the faiths of the marches
#               Frontier   (military)          watchmen on the Carpathian passes
#
# What makes them a choice and not six free bonuses:
#
#  - PRICE. Enacting costs 50 monarch power of the kind the ordinance's trade
#    suggests, as in the sibling mechanics and vanilla's own buttons
#    (rip_vln_magnate_senate.txt, 06_devshirme.txt): `<kind>_power_cost` in the
#    trigger block puts the price in the tooltip and checks it can be paid, in
#    the effect block the same name pays it.
#  - A TERM. An enacted ordinance is a country modifier of 3650 days. The
#    modifier is the single record of "in force": no flag, no sweep, no way for
#    the state to drift from the button, and every button refuses itself while
#    its own modifier stands (custom_trigger_tooltip ..._not_in_force_tt). The
#    crown cannot take an ordinance back; it waits it out.
#    NO ENGINE COOLDOWN (cooldown_years = 0 on every button). An earlier revision
#    put a ten-year cooldown_token of its own on each button so the tooltip would
#    name the date. Seen in EU4 1.37.5 on 2026-10-22: enacting ONE ordinance put
#    the red line "This Ordinance can only be used once every 10 years" on the
#    other five and turned all six icons grey, while the status panel still said
#    "Ready" - the engine did not keep the tokens apart, so only one ordinance
#    could be had per ten years and the three slots were a fiction. The modifier's
#    own end date is shown in the button tooltip ("Halych gets ... until ...").
#  - THREE SLOTS. At most three of the six can be in force. hlc_ordinance_slot_
#    free (common/scripted_triggers/rip_hlc_ordinance_triggers.txt) counts the
#    modifiers and every button requires it, so a fourth ordinance can be had
#    only when one of the three has run its course.
#  - THE AI. Every button has an ai_chance: it enacts what its realm needs
#    (settlement when several owned cities hold a culture that is neither
#    primary nor accepted, the cadastre when short of money and the nobles are
#    loyal, the urbarial dues where the land is restless, toleration where
#    other faiths fill the towns, the frontier guard in war, the chancery
#    otherwise). The situations are the *_wanted triggers in the same file.
#  - CLEAN-UP. hlc_crown_authority_reform.removed_effect and a yearly sweep
#    (hlc_ordinance_sweep_effect, common/scripted_effects/rip_hlc_ordinance_
#    effects.txt) take every ordinance out of force once the crown authority
#    that enacted them is gone, and move the permanent ordinances of an older
#    save onto the ten-year term.
#
# Layout: SIX buttons, two full rows of three, the order below. The bottom row
# sits below the fold of vanilla's mechanics list at small window heights; the
# wheel scrolls to it. That is a limit of the vanilla window which the author
# has been told about, not something this file can change. Each button has its
# own sprite (interface/rip_ability_icons.gfx), drawn by
# tools/build_government_ability_icons.py. The status panel in the government
# window (tools/build_government_status_ui.py) gives each ordinance a row that
# says whether it is in force, ready or why it is not.
#
# Buttons-only, same as rip_hlc_boyar_council.txt: no powers, no .gui, no DLC
# gate.
# =============================================================================
