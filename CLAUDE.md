# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Що це за репозиторій

Це не програмний проєкт, а мод для Europa Universalis IV (Clausewitz engine):
скриптові файли гри (`.txt`), локалізація (`.yml`), історія провінцій/країн і
графічні дескриптори (`.gfx`). Python у `tests/` — лише інструменти
статичної перевірки цього скрипту, не частина мода.

**Спершу читайте `docs/HANDOFF.md`** — це точка входу з поточним станом мода,
числами перевірок і переліком рішень, що чекають на автора. Він описує деталі,
яких тут навмисно немає, щоб не дублювати.

Актуальний звіт щодо реалізації від 7 вересня 2026 року:
`docs/AUTHENTICITY_IMPLEMENTATION_137.uk.md`. EU4 1.30.3 використовується лише
як збережений донор; статичні зіставлення виконані зі встановленою 1.37.5.
Нижче старі кількості перевірок збережені як контекст; актуальний перелік —
у `tests/run_all_tests.py`, повний журнал можна записати опцією `--log`.

## Критичне структурне правило

Корінь цього репозиторію — і тільки він — є ігровим коренем мода
(`descriptor.mod` тут же). **Не створюйте вкладених `descriptor.mod`,
вкладених Git-репозиторіїв чи файлів поза теками, які завантажує EU4.**
Рушій читає рівно ці теки з кореня:

```
common/  decisions/  events/  history/  interface/  gfx/  localisation/
missions/  customizable_localization/  sound/
```

`docs/`, `tests/`, `tools/`, `diagnostics/`, `.claude/`, `.venv/` гра не читає
взагалі — безпечне місце для нескриптових файлів. `tests/dev_tools/` навмисно тримає
файли поза цими теками (наприклад, налагоджувальну подію) — вони мертві, доки
їх не скопіювати назад.

Деталі міграції на канонічний корінь, дозволені винятки з розташувань і
семантика простору імен ID (`rip_vol_...`) — `docs/CANONICAL_ROOT_MIGRATION.md`.

## Команди перевірки

Усі скрипти запускаються з кореня мода звичайним `python`, без pytest і без
залежностей поза стандартною бібліотекою:

**Гейт злиття — один прогін:**

```powershell
python tests/run_all_tests.py
```

Він запускає **всі шістнадцять** перевірок і друкує підсумок
`ALL CRITICAL TESTS PASS`. Критичними вважає всі, **крім
`check_script_layer.py`** — та єдина може завершитись ненульовим кодом і не
завалити гейт, бо в ній лишені навмисні рішення для автора.

| Перевірка | Що тримає |
|---|---|
| `check_clausewitz_braces.py` | BOM і баланс дужок |
| `check_ro_blessing_window.py` | нативна панель православ'я: 95% ванільних чисел, відсутність GUI-оверрайдів, прибирання спадщини |
| `check_culture_key_compatibility.py` | ключі культур проти ванільних |
| `check_estate_layer.py` | стани, розділені по країнах |
| `check_event_modifier_layer.py` | **дублікати й змішування country/province API** — найтиповіша тиха помилка |
| `check_opinion_modifier_layer.py` | модифікатори думки: унікальність і використання |
| `check_province_names.py` | назви провінцій: ID, ареї, кодування, шарування |
| `check_government_reforms.py` | реформи: тири, гейти, життєвий цикл |
| `check_government_names.py` | назви урядів: пріоритет і досяжність |
| `check_glossary.py` | топоніми й регістр в англійській локалізації |
| `check_claim_pacing.py` | темп претензій KIE/KRU та Росії |
| `check_subject_cb_limits.py` | тривалість і винятковість CB на васалів |
| `check_border_principalities.py` | прикордонні/касимовські події проти опису |
| `check_steppe_expansions.py` | донські/черкеські/кафські ланцюги проти опису |
| `check_docs_language.py` | частка перекладеної документації (`--list` покаже рядки) |
| `check_script_layer.py` | структура, кодування, локалізація, досяжність, картинки, ID провінцій |

Кожен скрипт запускається й окремо і завершується кодом 1 при порушенні.

**Чого ці шістнадцять не бачать.** Усі вони — статичні контракти над текстом
скрипту. Жодна не рахує ігрову арифметику: механіка може бути бездоганно
з'єднана, пройти всі гейти й при цьому навертати цілу державу за один такт.
Числа перевіряють окремо, поза грою — `tests/dev_tools/balance_sim/`.

`check_script_layer.py` шукає встановлену EU4 сам (`EU4_DIR` або типові шляхи
Steam); без неї локалізаційні перевірки переходять у режим попереджень, а не
здогадів — **не довіряйте числу помилок без встановленої гри**. Задати шлях:

```powershell
$env:EU4_DIR = "D:\...\steamapps\common\Europa Universalis IV"
```

`check_docs_language.py` і `check_border_principalities.py`/
`check_steppe_expansions.py` прив'язані до тексту конкретних `docs/*.md` —
перейменування розділу там навмисно валить тест, бо саме так він ловить
розходження опису з кодом.

Оснастка ігрових прогонів-спостережень (`tests/observer/run_observer.ps1`) —
окремий важчий інструмент для балансових перевірок Milestone 3, з власним
`README.md`; не запускати без потреби, вона стартує сам EU4.

## Найважливіше архітектурне правило

**Мод успадковує від ванілі більше, ніж здається.** Наївна перевірка, яка не
враховує встановлену ваніль, дає сотні хибних спрацювань (415→0 помилок
локалізації, 215→89 картинок подій, 111→14 перейменувань провінцій — реальні
випадки з `docs/HANDOFF.md`). Перш ніж вважати щось відсутнім чи хибним,
перевірте, чи не дає це ваніль.

Інші повторювані пастки цього кодового рівня:

- **Реформа, якої немає в `common/governments/00_governments.txt`, ніколи не
  з'являється в грі**, хоч би що казали її `potential` і `trigger` у файлі
  реформ. Симптом — «реформа є у файлі, але її ніде не видно»; шукати причину
  треба в тирах governments, не в самому файлі реформи.
- **Реформа без блоку `potential` видно всім країнам світу**, лише притлумлену
  тригером. Єдиний гейт видимості — `ruthenian_reform_visible` з
  `common/scripted_triggers/ruthenian_reform_triggers.txt`.
- **Порядок перекриття локалізації визначає ім'я файлу за абеткою** — файл, чиє
  ім'я стоїть пізніше, виграє. Звідси префікс `zzz_` на файлах, які мають
  свідомо перекрити щось раніше (`localisation/zzz_*`,
  `localisation/replace/zzz_RIP_*`).
- **Перекривати ванільний ключ (наприклад, `PRINCIPALITY`) можна лише
  навмисно й із приміткою** — інакше це тихо перейменовує весь ванільний
  контент, що використовує той самий ключ.
- **Іконки в `.gfx`-стрічках (`interface/*.gfx`) нумеруються кадрами** — `icon
  = N` це позиція в одній із трьох стрічок спрайту, а не довільний номер.

## Тексти й локалізація

`docs/STYLE_GLOSSARY.md` — гейт злиття, але **не виконуваний документ**.
`check_glossary.py` звіряє англійську локалізацію з правилами розділів 1 і 3,
проте самих правил у документі не читає: вони вписані в її код (файл згадує
глосарій лише в докстрінгу, а відкриває тільки `localisation/*.yml`). Тобто
змінивши глосарій, ви **не** змінюєте гейт — обидва треба правити разом.
Головне з нього:

- Українські топоніми для власної території мода (Kyiv, не Kiev; Halych, не
  Galich), усталені англійські — для того, що поза нею (Dnieper, не Dnipro).
  Розділ 4 фіксує свідомі винятки на рівні тегів країн (`VLN` = Volyn, `POD` =
  Podolia, `KHK` = Kharkov Host) — не «виправляти» їх без перегляду системи
  назв.
- Називати установу, а не абстракцію («the Rada elects the hetman», не
  «democratic traditions»); уникати `identity`, `democracy`, `ethnic`,
  `ideology` та знаків оклику.
- Мова-джерело англійська; французька/німецька/іспанська успадковують з неї
  через `localisation/replace/zzz_RIP_untranslated_l_*.yml` і оновлюються лише
  коли перекладач їх бере.

Документація мода (`docs/*.md`) — українською; `check_docs_language.py`
рахує лише прозу (код, ID, шляхи, промпти для зображень і BBCode Steam-вітрини
до знаменника не входять і ніколи не дадуть «100%»).

## Паралельні сесії

Інші сесії реально комітять у ті самі файли між чатами. Перед злиттям завжди
`git fetch` і перевіряйте, чи `main` не пішов уперед, перш ніж покладатися на
числа помилок із попереднього прогону перевірок.
