# Локальна мережа як підагент

Сервер: llama.cpp, OpenAI-сумісний `http://localhost:8080/v1/chat/completions`.
На цій машині — `Codestral-22B-v0.1 Q3_K_M`, 4 слоти, `n_ctx = 8192`, без tool
calling. Бібліотека — `tests/dev_tools/local_llm.py`, довідка по API —
`tests/dev_tools/LOCAL_LLM_GUIDE.md`.

Це **генератор дешевих чернеток**. Не рев'юер, не аналітик, не джерело фактів.
Нижче — чому саме так, із числами.

## Заміряні межі

Прогін `.claude/skills/local-llm/scripts/benchmark.py` на реальних даних
`common/province_names` з обчисленою істиною. Швидкість: 3.0 ток/с на потік,
4.1–6.6 ток/с сукупно на чотирьох слотах.

| Архетип задачі | Результат | Що сталося |
|---|---|---|
| **B. Детермінована трансформація рядка**<br>«прибери апострофи» | **93–97 %** (28–29/30) | Найкращий режим. Але й тут тихо псує: загубив літеру (`Helsynhfors` → `Helsynhfor`), прибрав дефіс разом з апострофом |
| **Генерація коротких назв**<br>заголовки opinion modifiers | **8/8 за формою, 0/8 за якістю** | Формат гарантовано валідатором. Двом різним ключам видав однаковий рядок. Усі вісім переписано вручну |
| **C. Бінарне фактичне судження**<br>«засноване після 1750?» | **55 %** (11/20) | Відповів `NO` на всі 20. Із дев'яти анахронізмів не впізнав **жодного** |
| **A. Бінарна класифікація**<br>«в межах мода чи поза ними?» | **11 %** (4/38) | Відповів `INSIDE` на всі 38. Константа завжди-більшість дала б 89 % |
| **D. Аналіз/аудит**<br>корпус чистий, єдина правильна відповідь `NONE` | **0/1**, нестабільно | Три прогони, три різні поведінки: двічі вигадав порушення, яких немає (один раз назвав «записами» текст коментарів), раз відповів по суті правильно — але прозою, порушивши контракт виходу. Тобто навіть коли не помиляється, результат не машиночитний |

**Головний висновок: на бінарних питаннях модель колапсує в константу.**
Вона не «трохи помиляється» — вона видає одну відповідь на всю партію, і
валідатор формату цього не бачить, бо кожна відповідь окремо правильної форми.
На класифікації A це гірше, ніж не питати взагалі.

**Другий висновок: провал асиметричний.** У C усі 11 правильних — це клас `NO`,
усі 9 помилок — клас `YES`. Тобто модель ніколи не каже «тут щось не так».
Саме тому їй не можна давати пошук помилок: вона систематично сліпа до
позитивного класу.

**Третій висновок: на аналітичній формі задачі модель перестає тримати контракт
виходу.** На коротких генеративних і трансформаційних задачах вона віддає рівно
те, що просили; щойно її просять «перелічити порушення», вона починає писати
абзац. Це не косметика: партію в такому режимі неможливо валідувати механічно.

## Правило маршрутизації

**Віддавати локальній моделі**, коли одночасно виконано все:

1. задача розпадається на **десятки–сотні незалежних одиниць**;
2. вихід на одиницю — **один короткий рядок** (довжина виходу це вся ціна:
   900 токенів ≈ 5 хвилин, 15 токенів ≈ 5 секунд);
3. **усі потрібні факти вже в промпті** — нічого згадувати не треба;
4. форму відповіді можна **перевірити кодом**;
5. зміст усе одно **проходить огляд людини** перед записом у файл.

Типове: англійські назви модифікаторів, короткі тексти опцій подій, ключі
локалізації за шаблоном, механічні перетворення рядків.

**Не віддавати ніколи:** аудит скрипту, перевірку scope чи ID провінцій,
звірку з ваніллю, досяжність подій, пошук багів, історичну верифікацію,
класифікацію за змістом, вільний багатореченнєвий текст. Для всього цього в
моді є детерміновані перевірки — `tests/run_all_tests.py`, тринадцять гейтів.
Вони не помиляються; модель помиляється систематично.

**Межовий випадок — обсяг.** На 8 одиницях виграш ~10 секунд і не вартий
накладних витрат на промпт і валідатор. Поріг окупності починається десь від
кількох десятків однотипних рядків.

## Контракт промпту

```text
You generate one short draft only from the facts below.
Do not verify facts, find errors, or invent missing information.
Return only the requested format, with no explanation.
If the format cannot be met, return REJECT.

Task: <одна атомарна робота>
Facts: <лише перевірені факти, потрібні для цієї одиниці>
Answer contract: <точна довжина, словник, форма виходу>
```

Збирається через `constrained_prompt()`. Одна задача — один незалежний рядок.
Не передавати корпус файлів, історичні припущення, вивід перевірок або
попередню невдалу відповідь.

## Дві пастки харнеса

Обидві коштували повного прогону бенчмарка, обидві виправлені в
`local_llm.py` — але вони повертаються щоразу, коли хтось пише свій цикл.

**1. Обрізаний стоп-маркер.** При малому `max_tokens` шаблон чату
дописує `<|im_end|>`, і його ріже посередині: приходить `INSIDE<|im_`.
Розбиття по цілому маркеру такого не чистить, валідатор відхиляє **всі**
відповіді, прогін читається як 0 %. `_clean()` тепер зрізає й будь-який
префікс маркера. Тримайте `max_tokens` із запасом.

**2. `unique` на класифікації.** Дедуплікація відповідей правильна для
генерації (модель видає той самий рядок двом ключам, чий промпт різниться
одним власним іменем) і згубна для класифікації — там повтори законні. З
`unique=True` закритий набір відхилив **58 із 58** відповідей правильної форми.
Тому `unique` за замовчуванням **вимкнено**; вмикати явно і лише коли кожна
задача мусить дати свій рядок.

Загальний урок: **валідатор формату не є валідатором змісту.** Він однаково
пропускає і слушну відповідь, і константу на всю партію. Коли задача бінарна,
дивіться на розподіл відповідей у партії, а не лише на частку прийнятих.

## Ланцюг перевірки

Модель **ніколи** не редагує `.txt` чи `.yml` напряму. Порядок такий:

1. `preflight(tasks)` — сервер живий, партія влазить у 8192;
2. `run_batch(...)` — механічний валідатор, один повтор при `temperature=0`;
3. **огляд людини** — зміст, історичність, глосарій;
4. ручне внесення у файл;
5. гейти мода: `python tests/check_glossary.py` після локалізації,
   `python tests/check_clausewitz_braces.py` після скрипту, а перед злиттям —
   `python tests/run_all_tests.py` із виставленим `EU4_DIR`.

Кеш і звіти (`local_llm_cache.jsonl`, `local_llm_report.jsonl`) — тимчасові
файли розробки. До мода й до коміту не додавати.

## Відтворити заміри

```bash
python .claude/skills/local-llm/scripts/benchmark.py
```

Потребує запущеного сервера й встановленої ванілі (`EU4_DIR`, див.
`docs/HANDOFF.md`). Прогін ≈ 4 хвилини. Якщо міняється модель або квантизація —
переганяти й оновлювати таблицю вище, бо все правило маршрутизації тримається
на цих числах, а не на загальних міркуваннях про LLM.
