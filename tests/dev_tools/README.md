# Інструменти розробки

Гра цього не завантажує. EU4 читає `events/` і `localisation/` тільки в корені
мода, тож усе, що лежить тут, лишається мертвим, доки його не скопіюють назад.

## ZAZ_branch_debug

Перекидає запорізьке дерево на будь-яку з п'яти союзних гілок: чистить прапорці
`zaz_allied_*`, ставить один із них і викликає `swap_non_generic_missions`.
Подія має `is_triggered_only`, і ніщо її не викликає, тож дістатися до неї можна
було лише з консолі — саме тому їй і не місце в збірці для гравців.

Щоб скористатися нею під час випробувань, скопіюйте обидва файли назад до
`events/` і `localisation/`, а тоді в консолі:

```text
event zaz_branch_debug.1
```

Перед пакуванням приберіть їх знову.

## RIP_OldBelieverTest

Три приховані події-фікстури (`rip_ob_test.1-3`) для консолі: засівають
старообрядницькі громади, ставлять політику терпимості й перевіряють, що
громади, більшість і політика переживають кінець Розколу
(`rip_faith_disaster.2`). Результат пишуть у `game.log` маркерами
`RIP_OB_TEST MINORITY_PASS`, `POLICY_PASS`, `LOCAL_PASS`, `PERSISTENCE_PASS`.

Фікстура працює на цьому дереві: вона викликає `rip_ob_begin_schism_effect`,
`rip_ob_tolerate_effect` і `rip_ob_upkeep_effect`, які визначає
`common/scripted_effects/rip_old_believer_effects.txt`. Вихід Розколу
(Патріарший авторитет нижче 60%) маркером не перевіряється: катастрофу не можна
запустити до 1666 року без перезавантаження дати. Тримайте файл тут, а не в
`events/`: в `events/` гра завантажує його як живий, а
`tests/check_old_believers.py` це забороняє.

Щоб скористатися: скопіюйте `RIP_OldBelieverTest.txt` до `events/`, а
`rip_ob_test_l_english.yml` до `localisation/`, запустіть `event rip_ob_test.1`
за MOS на одноразовій кампанії без Ironman і приберіть обидва файли перед
пакуванням.

## RIP_GovernmentReformTest — усі реформи урядів одним меню

Меню консольних подій: по одному пункту на кожну реформу уряду RIP (123 реформи,
129 варіантів: `chr_grain_directorate_reform`, `uzh_*` та ще кілька стоять у двох
типах уряду, тож мають по пункту на тип). **Вибір пункту сам видає країні всі умови
реформи, а тоді й саму реформу** — тег, віру, культуру й прапорці шляху змінювати
наперед не треба.

Файли породжує `make_government_reform_test.py` з `common/governments`,
`common/government_reforms` і скриптових тригерів, які реформи викликають. Руками їх
не правте; після зміни реформ, тирів чи тригерів перегенеруйте:

```powershell
python tests/dev_tools/make_government_reform_test.py
```

### Як користуватися

```powershell
python tests/dev_tools/make_government_reform_test.py --install
```

Команда копіює події до `events/`, а текст до `localisation/`. Запустіть
одноразову кампанію **без Ironman** (будь-яка держава) і введіть у консолі
`event rip_gov_test.1`. Меню складається з двох сторінок груп (CHR, HET, ZAZ, KIE і KRU, HLC,
VLN, PDL, PRL, UZH, LIT, ODS і дві групи спільних реформ) і сторінок по сім реформ. Після
вибору реформи з'являється вікно результату: що видано, чого видати не можна,
кнопки «Next reform» / «Previous reform». Одну реформу можна взяти й без меню:
`event rip_gov_test.<1000 + №>` застосовує її мовчки, `<2000 + №>` показує вікно
результату; номер № стоїть у першому стовпці таблиці `--report`. Після випробувань:

```powershell
python tests/dev_tools/make_government_reform_test.py --remove
```

`tests/check_government_reform_fixture.py` у гейті не пропустить копії, що лишилися в
`events/` чи `localisation/`.

**Це руйнівна фікстура.** Вона переносить країну на інший тег: якщо тег займає жива
держава, вона спершу її `inherit`, тобто поглинає. Вона міняє віру й основну культуру,
перемикає тип уряду та ставить прапорці, які читає решта мода. Лише для одноразової
кампанії.

### Що робить один пункт

Пункт викликає приховану подію `rip_gov_test.1000 + n`, а тоді вікно результату
`rip_gov_test.2000 + n`:

1. **Скидає уряд.** Перемикає на інший тип і назад: так лишається тільки базова
   реформа типу (перемикання на *той самий* тип реформ не скидає, виміряно).
   Знімає також усі прапорці, які читають умови реформ.
2. **Видає умови** з `potential` і `trigger` реформи, розгорнувши скриптові тригери:
   тег (`change_tag`), віру, основну культуру, прапорці шляху, попередні реформи разом
   з умовами їхнього власного шляху, технології, військову традицію, професійність
   армії, живу силу, розвиток провінцій. З кількох гілок `OR` береться найдешевша
   сумісна: «тег + прапорець шляху» дешевший за «володій іншою реформою родини».
3. **Звіряє видане**: для кожного пункту, якого не вистачає, пише
   `RIP_GOV_TEST GRANT_FAIL <реформа> <тип> <що>`.
4. **Перевіряє себе**: обчислює `potential` і `trigger` реформи, скопійовані дослівно,
   **до** її додавання й пише `POT_OK` / `POT_FAIL` і `TRG_OK` / `TRG_FAIL`.
5. Додає реформу й пише `HELD_OK` або `HELD_FAIL`.

Усі маркери йдуть у `logs/game.log` у теці даних користувача.

### Батарея й звіт

Пункт «Run all 129 reforms and log the result» на першій сторінці проганяє всі варіанти
підряд без вікон. Після цього:

```powershell
python tests/dev_tools/make_government_reform_test.py --report
```

Звіт читає `game.log` (або файл, наведений після `--report`) і друкує таблицю
POT / TRG / HELD по кожній реформі. Код виходу 1, якщо якась реформа не виконана, не
видана чи не лишилася в країні без відомої причини.

### Чого скрипт видати не може

Ці десять варіантів позначені в меню зірочкою; їхній `POT_FAIL` / `TRG_FAIL` очікуваний
на старті 1444.11.11 (у грі з пізнішою датою умова може виконатися сама, і звіт це покаже):

| Реформа | Чого бракує |
|---|---|
| `het_mazepist_autocracy_reform` | рік 1687 |
| `zaz_free_host_reform` | рік 1650 |
| `zaz_last_sich_reform` | рік 1734 і статус васала |
| `uzh_union_synod_reform` (monarchy і republic) | рік 1646 |
| `vln_ruthenian_renaissance_reform` | інститут Відродження, якого на старті немає |
| `pdl_enlightened_voivodeship_reform` | інститут Просвітництва |
| `pdl_revolutionary_republic_reform` | епоха революцій |
| `het_collegium_control_reform`, `principality_appanage` | умови називають лише саму реформу: її дає тільки скрипт |

Дві з них (`pdl_enlightened_voivodeship_reform`, `pdl_revolutionary_republic_reform`) ще й
**не лишаються в країні**: `add_government_reform` перевіряє умови реформи вже після
додавання, і реформа, чиї умови не називають саму себе (`has_reform = вона сама`),
відкочується, поки вони не справдяться (так само поводиться ванільна
`enlightened_monarchy_reform`, а `pdl_clan_assembly_reform` без тегу PDL). Тому фікстура
здатна видати лише ті реформи, умови яких справді виконано.

### Виміряно в EU4 1.37.5 (чого не видно зі скрипту)

- `country_event`, викликаний з ефекту, виконується **негайно й вкладено**, а не в черзі.
- Після `change_tag` країна переїжджає в новий об'єкт, а подія, вистрелена зі старого
  `ROOT`, діє на мертвий: `change_government` і `change_tag` мовчки нічого не роблять, а
  прапорці й реформи лягають на країну, якою ніхто не грає. Тому все, що йде після можливої
  зміни тегу, адресується людській державі наново (`every_country = { limit = { ai = no } ... }`).
- `change_tag` на тег без провінцій працює; на живий тег потрібно спершу `inherit`.
- `add_government_reform` приймає реформу будь-якого типу уряду (тип не міняється) і сам
  заміщає реформу з того ж тира.
- `republican_tradition` у монархії не росте; `add_institution_embracement` не вмикає
  інститут, якого ще немає на карті; `army_size_percentage` ≥ 1 потребує модифікатора
  ліміту війська (у фікстуру не входить).
- `else` / `else_if` фікстура не вживає: рушій 1.37.5 губить деякі ефекти в їхніх тілах.

## local_llm — локальний llama.cpp як підагент

`local_llm.py` — пул запитів до llama.cpp на `http://localhost:8080`
(Codestral-22B Q3_K_M). Гра цього не читає; це інструмент розробки.

Повний універсальний контракт, готові валідатори, кешування й приклад пакетного
запуску — у [LOCAL_LLM_GUIDE.md](LOCAL_LLM_GUIDE.md).

Заміряно на цій машині: **3.0 ток/с** на потік, **4 слоти**, `n_ctx = 8192`.
Звідси все інше.

**Чого йому не давати.** Аналізу. На проханні звірити вісім файлів
`common/opinion_modifiers` з п'ятьма правилами ванілі він вигадав вісім
порушень, яких немає («у podillia немає `yearly_decay`» — він там у всіх
п'яти), і не побачив жодного справжнього (`max = -N`, `yearly_decay = -1`).
Q3-квантизація галюцинує саме заперечення — «тут бракує X». Ніколи не питайте
його, що з чимось не так.

**Що він робить добре.** Одну коротку рядкову відповідь із фактів, які вже
лежать у промпті. Довжина виходу — це вся ціна: 900 токенів це п'ять хвилин,
15 токенів це п'ять секунд.

**Робочий шаблон:**

1. одне завдання на одиницю роботи, усі факти вписані в промпт;
2. жорсткий контракт виходу (`Title Case`, 2–6 слів, без лапок) і `stop`;
3. `check` — механічний валідатор на кожну відповідь;
4. `run_batch` жене їх по 4 слотах, відхилене перезапитує раз при `temperature=0`,
   решту віддає людині.

```powershell
python tests/dev_tools/local_llm.py     # самоперевірка на живому сервері
```

**Чого валідатор не ловить — і чому є `unique=True`.** `check` бачить лише свою
відповідь. На восьми заголовках модифікаторів думки модель видала однакове
«Ruthenian Recognition Status» і для Литви, і для Польщі — обидві пройшли
формат. Тому `run_batch` за замовчуванням відхиляє відповідь, що збігається з
чужою.

**Реальна віддача.** 8 заготовок за 26 с (6.6 ток/с сукупно) проти ~16 с
послідовно. Формат гарантовано, якість — ні: усі вісім довелося переписати.
Тобто це чернетковий генератор для об'ємної однотипної роботи, а не автор.
Для 8 рядків виграш невеликий; для 200 — відчутний.

## balance_sim — арифметика механік поза грою

`balance_sim/` містить дві моделі на C++, які повторюють числа релігійних
механік там, де їх видно. Скрипт EU4 рахує бюджет навернень усередині
`while`-циклу, який не має способу нічого надрукувати; статичні перевірки
доводять, що символи з'єднані, і не можуть сказати, що механіка перетворює цілу
державу за один такт.

На трьох запусках моделі знайшли три справжні дефекти, яких не спіймав жоден
гейт: бюджет без десятини, недосяжний найдешевший тир для малих держав і
таблицю утримання ікон, за якої за 200 років жодна лампада не гасла. Подробиці
й таблиці — у `balance_sim/README.md`.

Запуск (компілятора немає в `PATH`, потрібен `vcvars64.bat`):

```powershell
powershell -File tests/dev_tools/balance_sim/build_and_run.ps1
```
